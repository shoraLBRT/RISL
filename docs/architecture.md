# Устройство приложения

Документ объясняет принятые решения и их причины — то, что не видно из кода, но
без чего его легко сломать при доработке.

## Публичная часть работает без интерактивного режима Blazor

Ни один гостевой запрос не открывает WebSocket: страницы отдаются обычным
серверным HTML. Скриптов фреймворка на страницах тоже нет — только собственный
`app.js` на полторы сотни строк. Поэтому сайт не показывает «Переподключение…»
на плохой мобильной связи, полностью индексируется поисковиками и работает при
выключенном JavaScript: теряются только поиск по мере ввода, избранное и кнопки
скорости.

## Почему не используется `blazor.web.js`

Он умеет подменять части страницы без перезагрузки, но при публикации SDK
выбрасывает его из приложения, где нет ни одного интерактивного компонента. В
разработке всё работало бы, а в собранном образе молча перестало.

Поэтому подмена блока результатов при поиске сделана своими силами: обычный
`fetch` той же страницы, перенос содержимого `[data-results]` и
`history.pushState`. Поведение одинаково в разработке и в продакшене, а кнопка
«назад» возвращает прошлую выдачу.

## Весь публичный словарь живёт в памяти

Снимок из трёх тысяч статей занимает считанные мегабайты и перечитывается
целиком после каждой записи в админке (`SearchIndexMaintainer`). Гостевые
страницы не делают ни одного запроса к базе.

## Морфологии в поиске нет

Запрос «кошками» не найдёт «кошка». Ранжирование: точное совпадение слова →
слово начинается с запроса → слово содержит запрос → совпадение в определении.

## Слово видно гостю, только если оно опубликовано и видео обработано успешно

Карточка с провалившейся обработкой в выдачу не попадёт.

## Параметры строки запроса принимаются только строками

Штатная привязка Blazor к `bool` или `int` выбрасывает исключение на любом
неразобранном значении, и вместо страницы пользователь получает ошибку — уронить
её может опечатка в адресе или обход поискового робота. Все такие параметры
объявлены как `string?` и приводятся через `QueryValues`; правило закреплено
тестом, который обходит сборку рефлексией.

## Структура решения

```
RISL.Domain          сущности и нормализация текста, без внешних зависимостей
RISL.Application     порты, поисковый индекс, разбор CSV, хеширование пароля
RISL.Infrastructure  EF Core/SQLite, файловое хранилище, ffmpeg, фоновые службы
RISL.Blazor          страницы, эндпоинты форм, статика
RISL.Tests           xUnit: поиск, импорт, хранилище, админ-сервисы
```

Зависимости идут строго в одну сторону: `Blazor → Infrastructure → Application → Domain`.

## Обработка видео

Загруженный файл проверяется через `ffprobe` и ставится в очередь. Фоновая
служба обрабатывает задания по одному (ffmpeg упирается в процессор) и приводит
запись к виду, который проигрывает любой браузер:

```
H.264 high, yuv420p, ширина до 1280, CRF 24, +faststart, AAC 96k
```

`yuv420p` обязателен — без него часть мобильных браузеров покажет чёрный экран;
`+faststart` двигает индекс в начало файла, чтобы видео стартовало без полной
загрузки.

Незавершённые задания хранятся в базе, поэтому **перезапуск контейнера их не
теряет**: при старте всё, что осталось в состояниях «в очереди» и
«обрабатывается», ставится в очередь заново. Если ffmpeg не справился, слово
получает состояние «Ошибка» с текстом причины и кнопкой «Повторить обработку» в
карточке.

Кодирование идёт во временный файл `*.part`, и только полностью готовый
результат переставляется на место. Раздача статики такие файлы не отдаёт, а
уборка при старте их удаляет — иначе каждый перезапуск во время обработки
оставлял бы на диске недокодированный ролик, на который никто не ссылается.

## Безопасность

- Роль одна: гость или администратор. Регистрации нет, пароль хранится только
  как PBKDF2-хеш (100 000 итераций, SHA-256).
- Cookie сессии: `HttpOnly`, `SameSite=Strict`, скользящее истечение 8 часов.
- Попытки входа ограничены пятью за 15 минут с адреса, отправка обратной связи —
  пятью в час. У формы обратной связи есть поле-приманка от простых ботов.
- Все формы защищены токеном от подделки межсайтовых запросов.
- Имена загружаемых файлов никогда не используются как пути: и форма, и архив
  импорта сохраняют файлы под сгенерированными именами, а хранилище
  дополнительно проверяет, что путь не выходит за свой корень.
