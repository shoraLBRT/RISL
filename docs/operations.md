# Развёртывание и эксплуатация

## Запуск в Docker

```bash
cp .env.example .env
```

Заполните `.env`. Соль и хеш пароля печатает служебная команда:

```bash
dotnet run --project RISL.Blazor -- hash-password ваш-пароль
```

Приложение без прокси, доступно на `http://localhost:8080`:

```bash
docker compose up --build
```

Вместе с HTTPS-прокси (нужен настоящий домен в `SITE_ADDRESS`):

```bash
docker compose --profile proxy up --build -d
```

Образ уже содержит ffmpeg. База и медиафайлы лежат на томе `./data` и переживают
пересборку.

## Конфигурация

Любую настройку можно переопределить переменной окружения, заменив `:` на `__`
(например `Media__KeepOriginals=false`).

| Ключ | По умолчанию | Назначение |
|---|---|---|
| `Database:Path` | `data/risl.db` | Файл SQLite. Каталог создаётся сам. |
| `Database:SeedSampleData` | `false` | Примеры для разработки. В продакшене должно быть выключено. |
| `Media:RootPath` | `data/media` | Корень хранилища. **Вне wwwroot** — иначе публикация затрёт загруженное. |
| `Media:KeepOriginals` | `true` | Хранить исходники. Позволяют перекодировать словарь заново без пересъёмки, но три тысячи роликов с телефона — это сотня гигабайт. |
| `Media:MaxUploadBytes` | 512 МБ | Потолок размера загружаемого файла. Должен согласовываться с `max_size` в Caddyfile. |
| `Ffmpeg:Crf` | `24` | Качество H.264: меньше — лучше и тяжелее. |
| `Admin:Login` / `Admin:PasswordSalt` / `Admin:PasswordHash` | пусто | Учётные данные администратора. Задаются только через окружение. |

## Наполнение словаря

Вносить три тысячи слов руками нереально, поэтому основной путь — **массовый
импорт** в разделе `/admin/import`.

CSV в UTF-8, разделитель `;` или `,` определяется автоматически. Колонки
(понимаются и русские, и английские названия):

| Колонка | Обязательна | Содержимое |
|---|---|---|
| `слово` / `word` | да | Само слово. Повтор внутри файла — ошибка строки. |
| `описание` / `description` | нет | Определение. |
| `категории` / `categories` | нет | Темы через `\|`. Отсутствующие создаются сами. |
| `видео` / `video` | нет | Имя файла внутри zip-архива. |

Импорт двухшаговый: сначала показывается отчёт с номерами строк, и только после
подтверждения данные пишутся в базу — одной транзакцией. Слово, уже имеющееся в
словаре, обновляется, поэтому **повторная загрузка того же файла безопасна**.

Из архива берутся только имена файлов; пути внутри игнорируются, а на диск всё
кладётся под сгенерированными именами. Архив с записью вида `../../evil.mp4`
ничего не перезапишет.

Перекодирование загруженных роликов описано в
[architecture.md](architecture.md#обработка-видео).

## Резервное копирование

База и медиафайлы бэкапятся **по-разному**, и это не откладывается «на потом»:
двадцать гигабайт видео снимались месяцами.

```bash
# База: копировать файл под нагрузкой нельзя, нужен встроенный механизм SQLite
sqlite3 ./data/risl.db ".backup '/backup/risl-$(date +%F).db'"

# Медиа: обычная синхронизация каталога
rsync -a --delete ./data/media/ /backup/media/
```

Восстановление: остановить контейнер, положить файл базы в `./data/risl.db`,
вернуть каталог `./data/media`, запустить контейнер. Миграции применятся сами.

Проверяйте восстановление на пустом окружении хотя бы раз в квартал — бэкап,
который ни разу не разворачивали, бэкапом не является.
